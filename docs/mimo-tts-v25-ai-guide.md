# MiMo V2.5 TTS AI 使用指南

本文档基于小米 MiMo 官方文档《语音合成（MiMo-V2.5-TTS 系列）》整理，用于指导 MyRadio 和其他 AI Agent 正确调用 TTS。

官方文档：https://platform.xiaomimimo.com/docs/zh-CN/usage-guide/speech-synthesis-v2.5

## 核心规则

MiMo V2.5 TTS 是 Chat Completions 风格接口，但 TTS 文本和控制指令的位置很重要：

- 目标朗读文本必须放在 `messages` 中 `role: assistant` 的 `content`。
- 自然语言风格控制放在 `role: user` 的 `content`。这部分不会被朗读出来。
- 音频标签控制放在 `role: assistant` 的 `content`，通常放在目标文本开头或句中。
- 流式调用的低延迟能力暂未上线，当前流式会降级为兼容模式。
- 非流式输出建议使用 `audio.format = "wav"`；流式兼容调用要求 `pcm16`。

## 三种模型选择

### `mimo-v2.5-tts`

用于预设精品音色。

适用场景：

- 需要稳定、开箱即用的音色。
- 用户选择了预设音色，如 `冰糖`、`茉莉`、`苏打`、`白桦`、`Mia`、`Chloe`、`Milo`、`Dean`。
- 需要唱歌模式。

注意：

- 不支持音色设计。
- 不支持音色复刻。

示例：

```json
{
  "model": "mimo-v2.5-tts",
  "messages": [
    {
      "role": "user",
      "content": "用温暖克制的私人电台 DJ 语气，语速中慢，停顿自然。"
    },
    {
      "role": "assistant",
      "content": "(温柔 深沉)欢迎回到 MyRadio，接下来这首歌会把今晚的情绪慢慢放低。"
    }
  ],
  "audio": {
    "format": "wav",
    "voice": "白桦"
  }
}
```

### `mimo-v2.5-tts-voicedesign`

用于通过文本描述设计音色。

适用场景：

- 没有预设音色，也没有参考音频。
- 想根据角色描述生成一个新音色。
- 适合一次性角色配音、实验音色、播客人设设计。

注意：

- `user.content` 是音色设计描述，必填。
- 不支持预设音色。
- 不支持音色复刻。
- 不支持唱歌模式。
- 可在 `audio` 中设置 `optimize_text_preview`。

示例：

```json
{
  "model": "mimo-v2.5-tts-voicedesign",
  "messages": [
    {
      "role": "user",
      "content": "一位三十岁左右的深夜电台男 DJ，声音低沉温暖，语速偏慢，普通话里带一点北方口音，像熟悉用户品味的朋友。"
    },
    {
      "role": "assistant",
      "content": "(深沉 温柔)这首歌不用急着进入，它更像把房间里的光线慢慢调暗。"
    }
  ],
  "audio": {
    "format": "wav",
    "optimize_text_preview": true
  }
}
```

### `mimo-v2.5-tts-voiceclone`

用于基于音频样本复刻音色。

适用场景：

- 用户上传了参考音频。
- 需要复刻某个固定声音。
- MyRadio 的自定义克隆音色模式。

注意：

- `audio.voice` 必须是带 MIME 前缀的 Base64 音频，例如 `data:audio/mpeg;base64,...`。
- 当前支持 `mp3` 和 `wav` 样本。
- Base64 字符串大小不能超过 10 MB。
- 不支持预设音色。
- 不支持音色设计。
- 不支持唱歌模式。

示例：

```json
{
  "model": "mimo-v2.5-tts-voiceclone",
  "messages": [
    {
      "role": "user",
      "content": "保持参考音色，但用私人电台 DJ 的方式朗读，语气温暖、克制，句子之间留出自然停顿。"
    },
    {
      "role": "assistant",
      "content": "(河南话 温柔 深沉)下一首我想放得近一点，让刚才的情绪有个更柔和的落点。"
    }
  ],
  "audio": {
    "format": "wav",
    "voice": "data:audio/mpeg;base64,..."
  }
}
```

## 风格控制

MiMo V2.5 TTS 支持两类控制：自然语言控制和音频标签控制。实际使用中应同时使用二者。

### 自然语言控制

自然语言控制放在 `user.content`，适合描述整体表演方向：

- 角色身份：私人电台 DJ、播客主持人、故事讲述者。
- 场景：深夜、专注工作、放松陪伴、主动推荐新歌。
- 语气：温暖、克制、低声、松弛、带发现感。
- 节奏：语速中慢、句间停顿、重点词轻强调。
- 禁忌：不要播音腔、广告腔、新闻播报腔、机械朗读。

示例：

```txt
你是一位私人音乐电台 DJ，正在介绍下一首歌。
声音温暖、克制、低沉，语速中慢，句与句之间留自然呼吸。
提到歌名和歌手时稍微更亲近一点，但不要像广告、新闻播报或朗读模板。
```

### 导演模式

导演模式也是自然语言控制的一种增强写法，放在 `user.content`，建议拆成三段：

- 角色：说话者是谁，声音底色是什么。
- 场景：此刻为什么说这段话，用户处在什么场景。
- 指导：具体表演方法，包括语速、停顿、气息、重音、情绪曲线。

MyRadio 推荐模板：

```txt
【角色】
你是 MyRadio 的私人电台 DJ，不是播音员。你了解用户的听歌品味，讲话像一个懂音乐的朋友。

【场景】
你正在音乐开始前做一段短独白，介绍这首歌、承接上一首歌的情绪，并说明为什么此刻推荐。

【指导】
声音温暖、克制、低沉；语速中慢；句间留自然呼吸。
重点词轻轻强调，情绪有弧线但不过度表演。
不要营销腔、新闻腔、鸡汤腔，也不要像念字段。
```

## 音频标签控制

音频标签放在 `assistant.content`。标签会被模型用于控制实际朗读，通常比只写自然语言 prompt 更直接。

### 整体风格标签

放在目标文本最开头：

```txt
(温柔 深沉)欢迎回到 MyRadio，接下来这首歌会把今晚的情绪慢慢放低。
```

支持半角括号、全角括号或方括号：

- `(温柔 深沉)`
- `（温柔 深沉）`
- `[温柔 深沉]`

推荐标签类别：

- 基础情绪：开心、悲伤、愤怒、恐惧、惊讶、兴奋、委屈、平静、冷漠
- 复合情绪：怅然、欣慰、无奈、愧疚、释然、嫉妒、厌倦、忐忑、动情
- 整体语调：温柔、高冷、活泼、严肃、慵懒、俏皮、深沉、清醒、松弛
- 音色定位：磁性、醇厚、清亮、空灵、稚嫩、苍老、甜美、沙哑、醇雅
- 人设腔调：夹子音、御姐音、正太音、大叔音、台湾腔
- 方言：东北话、四川话、河南话、粤语
- 角色扮演：孙悟空、林黛玉
- 唱歌：唱歌

### 方言标签

方言应作为 `assistant.content` 的音频标签，而不是只放在 `user.content` 中。

正确：

```txt
(河南话 温柔 深沉)下一首我想放得近一点，让刚才的情绪有个更柔和的落点。
```

不推荐：

```txt
user: 全程使用河南话。
assistant: 下一首我想放得近一点...
```

原因：官方文档明确音频标签控制放在 `assistant.content`，方言属于音频标签类别。

### 句中细粒度标签

可以在文本中插入细粒度标签控制语气、情绪、节奏：

```txt
(温柔 深沉)这首歌不是急着把情绪推高，[轻笑]它更像把灯光调暗一点。接下来，听王杰的《安妮》。
```

推荐谨慎使用：

- 语速与节奏：吸气、深呼吸、叹气、长叹一口气、喘息、屏息
- 情绪状态：紧张、害怕、激动、疲惫、委屈、撒娇、心虚、震惊、不耐烦
- 语音特征：颤抖、声音颤抖、变调、破音、鼻音、气声、沙哑
- 哭笑表达：笑、轻笑、大笑、冷笑、抽泣、呜咽、哽咽、嚎啕大哭

MyRadio 中不要滥用 `[笑]`、`[叹气]` 等标签。DJ 独白应该自然、有陪伴感，不要变成表演炫技。

## MyRadio DJ TTS 推荐策略

### 基础调用结构

```json
{
  "model": "根据音色模式选择",
  "messages": [
    {
      "role": "user",
      "content": "导演模式：角色 + 场景 + 指导"
    },
    {
      "role": "assistant",
      "content": "(风格标签 方言标签)目标独白文本"
    }
  ],
  "audio": {
    "format": "wav",
    "voice": "预设音色 ID 或参考音频 Base64"
  }
}
```

### 场景到标签的推荐映射

| 场景 | user 导演提示 | assistant 标签 |
| --- | --- | --- |
| 开场 | 有一点仪式感和欢迎感，慢慢把用户带入播放状态 | `(温柔 深沉)` |
| 专注 | 语气清醒、克制、不催促，帮助用户收回注意力 | `(平静 清醒)` |
| 放松 | 柔和、松弛、有呼吸感，不打扰 | `(温柔 慵懒)` |
| 深夜 | 低声、贴近、停顿更长，有陪伴感 | `(低声 深沉)` |
| BGM | 存在感低，少戏剧性，不抢音乐 | `(平静 克制)` |
| 探索推荐 | 有发现感和温柔笃定，像真的找到一首新歌 | `(欣慰 温柔)` |

### 方言与音色模式

方言是基础选项，适用于三种模型：

- 预设音色：`audio.voice` 使用预设音色，`assistant.content` 添加方言标签。
- 音色设计：`user.content` 描述音色，`assistant.content` 添加方言标签。
- 音色克隆：`audio.voice` 使用参考音频。若发现方言会明显改变克隆音色，应优先保持参考音色，只在 `user.content` 中弱化描述方言口音，不在 `assistant.content` 使用强方言标签。

注意：方言标签可能改变音色表现。预设音色通常可以使用强方言标签；克隆音色如果出现“像换了一个人”的问题，应把方言从强音频标签降级为导演提示，优先保留参考音色主体。

### 推荐的克隆 + 方言请求

```json
{
  "model": "mimo-v2.5-tts-voiceclone",
  "messages": [
    {
      "role": "user",
      "content": "保持参考音色的主体质感、年龄感、音色厚度和说话习惯，河南话只作为轻微口音倾向。不要为了河南话改变成另一种人声，不要夸张模仿方言演员。整段话要连贯成句，避免逐字停顿。整体像私人电台 DJ，温暖、克制、低声。"
    },
    {
      "role": "assistant",
      "content": "(温柔 深沉)下一首我想放得近一点，让刚才的情绪有个更柔和的落点。"
    }
  ],
  "audio": {
    "format": "wav",
    "voice": "data:audio/mpeg;base64,...",
    "optimize_text_preview": true
  }
}
```

## MyRadio 实现约束

- 方言默认不选定。
- 方言不属于“预设音色”的子功能，应作为基础选项，对预设、设计、克隆都生效。
- 缓存 key 必须包含：模型、音色模式、预设音色、克隆音频路径、音色设计描述、方言、风格版本、文本。
- 返回给前端的 hash 必须和实际合成时使用的配置一致。
- 旧 session 中已合成的 TTS 不会自动重合成；切换配置后应新建 session 或重新触发合成。
